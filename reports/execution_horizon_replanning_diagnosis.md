## 判断方式

对每局报告新旧chunk重叠区间的计划差异、边界命令变化和实际末端运动，再按episode等权汇总。单个较大跳变只能作为线索，不能直接定为失败原因；首次H分歧与最终成败之间也可能存在多个后续决策。

若回放可复现且差异集中于重规划边界，下一步优先做少量同状态介入，区分重新观察时机与旧计划接续的影响，再决定是否训练动作接续。若边界证据弱，转向候选自身整局回报/信用估计；若多个H在同状态都难恢复，检查更早偏差及恢复动作。只推进有证据支持的一项，不并行堆叠新模块。

这9个开发初态用于诊断，不转为梯度训练样本；后续训练使用训练初态，未使用的预留测试保持独立。判断和具体推进结果追加到本文件。

## 有效单点试验与推进决定

8个root共48个分支完整结束，根动作再生成差为0，每分支根物理状态通过一致性核对；Task9未复现而跳过。保持history原H成功22/24，首次换为A的H成功20/24，配对救回1次、退化3次。

| Task / episode | history首H成功/3 | A首H成功/3 |
| --- | ---: | ---: |
| 0/344 | 3 | 3 |
| 2/336 | 3 | 3 |
| 3/339 | 3 | 3 |
| 4/337 | 3 | 1 |
| 6/339 | 2 | 1 |
| 7/339 | 3 | 3 |
| 8/338 | 2 | 3 |

这不支持把首次H统一退回A，也不足以把原退化统一归因为提前观察或动作不连续。被动轨迹中，Task6/339、Task8/343退化时history边界命令变化反而较小，Task0/344、Task4/337救回时更大；命令变化与实际机械运动、成败之间不能直接等同。

独立审计发现更直接的问题：原history step450虽期望loss改善，部署argmax在60个早停root的缓存分支上仍为245/300，与A相同且RPC更高。于是优先推进[按实际部署决策选checkpoint](execution_horizon_greedy_selection.md)，不先改动作专家。复用数据及原650次训练轨迹后，current/history均选step200；current早停净多4次成功、只改2个root的H，优于history净多2次，因此只将current step200与A做同协议开发测试。完整200局评测中候选92/100、A93/100，候选RPC增加6.17%、整局增加4.06%，仅调整选模准则未超过A；本批结束，预留200初态未运行。
